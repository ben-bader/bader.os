# Component guidelines

- Give components a meaningful page or behavior boundary; do not componentize decorative fragments.
- Keep section components focused and server-rendered when their content is static.
- Use typed props for reusable project records and architecture flows.
- Prefer native anchors, lists, headings, and disclosures before custom interaction.
- Keep keyboard focus visible and provide touch-friendly targets.
- Do not add loading, animation, hover, or error states unless the component needs them.
- Keep project facts in the shared content model; do not copy them into components.
