# Three.js

The active route uses one lazy, fixed R3F scene behind the DOM. Its procedural B monogram and light field establish a spatial identity; section state moves the object and camera, and project focus gives it a restrained response.

Keep all content and project relationships in semantic DOM. Use one renderer, cap pixel ratio and particles by capability, reduce FBO resolution on mobile, stop rendering when the tab is hidden, and remove the Canvas for reduced motion. Dynamically load the client-only scene so the first HTML render remains usable without WebGL.

Project imagery must come from actual supplied assets. When no image exists, use recorded nodes and edges or leave the surface empty; do not fabricate product screens.
